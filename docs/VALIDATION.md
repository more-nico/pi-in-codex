### 守护进程升级回归

- 并发新客户端只替换一次旧构建；匹配的构建继续复用。
- 升级后未完成任务为“已中断”，历史及标记为不完整的结果保留，不自动重放。
- 旧客户端拒绝降级较新的守护进程；旧实例 ID 不能停止新实例。
- 迁移没有构建标识的 0.1.0 守护时，等待实际进程退出及锁/socket 释放。
- 退出超时、仍持锁但不响应时明确失败，安装器不继续替换文件。
- 安装器与首次启动共享生命周期锁，避免在文件替换期间启动另一份守护。

## 此前真实宿主与模型记录（0.1.0）

这些记录来自 2026-10-16/17 的本机验收，不代表已经在桌面安装中验收 0.1.1。

- `scripts/smoke-host.ts` 在隔离 CODEX_HOME 中通过原生插件添加/列表、app-server 发现
  四种 hooks、MCP 服务与 thread entrypoint，并在 MCP 调用中收到宿主当前 thread 元数据。
  兼容清单为 `.codex-plugin/plugin.json`；安装器解析实际 MCP/hook 脚本路径。
- 安装并信任 hooks、重启 Codex 后，Pi 面板成功挂载；真实 DeepSeek Max 子对话两轮完成，
  第二轮恢复前文，hooks 回传与 pi_ack 确认通过。
- 当前聊天两个 DeepSeek high 只读任务实际同时执行，开始相差约 0.18 秒、重叠约 14 秒，
  独立消息与完成 ID 正确，两个结果分别确认。
- `scripts/smoke-pi.ts` 是显式运行的真实模型测试，使用用户的订阅，未加入常规测试。
  原始运行报告保留在被忽略的 release 目录，不随源码、npm 包或 ZIP 发布。

## 面板性能优化（源码更新，尚未安装或发布）
