Codex 插件 · 独立的 Pi 子 agent

让 Pi 在旁边干活，
主聊天保持清爽

pi_in_codex 为当前 Codex 聊天启动独立的 Pi 子 agent，把你明确交给它的上下文带过去，并在只读侧面板里实时查看它的进展。这是独立社区项目，与 OpenAI、Earendil 没有隶属或背书关系。

本地安装 阅读文档

核心能力

围绕“隔离、可见、可控”设计，不替代你的主对话，只承接需要单独推进的子任务。

独

隔离的子 agent

每个 Pi 子任务运行在当前聊天之外，互不污染主对话的上下文与历史。

显

显式上下文

只传递你指定的文件、片段与说明，不会把整段聊天记录默认带过去。

览

实时只读侧面板

在侧面板观察子任务的输出与状态，查看过程而不会干扰它的执行。

导

steering 与 follow-up

运行中可以追加方向性指令（steering），也可以在结束后继续追问（follow-up）。

安

安全点回传

结果在安全的节点回传到主聊天，避免半成品随意插入你正在进行的讨论。

认

复用本地认证

直接沿用你机器上已配置的 Pi 本地模型认证，不需要为插件另行配置凭据。

工作方式

一次委派分为四步，每一步都在你的掌控之中。

  1. 发起在主聊天中说明任务，并明确指定需要传递的上下文。
  2. 隔离运行Pi 子 agent 在独立环境中执行，侧面板只读展示进展。
  3. 中途调整运行中用 steering 修正方向，结束后可用 follow-up 继续追问。
  4. 安全点回传结果在安全节点带回主聊天，历史完整保留以便回看。

注意：主聊天处于闲置时，插件不会自动唤醒它。子任务结果会在你的下一轮对话中被收取。

不是原生 Codex subagentpi_in_codex 调用的是独立的 Pi 子 agent，而非 Codex 内置的 subagent 机制。
不继承 Codex 沙箱Pi 子 agent 不会自动沿用 Codex 的沙箱限制，请按自己的安全要求评估与配置。

本地安装

目前支持 macOS。在仓库根目录依次执行下面四条命令即可完成本地安装与检查。

npm ci
npm run check
node bin/pi-in-codex.mjs doctor
node bin/pi-in-codex.mjs install
